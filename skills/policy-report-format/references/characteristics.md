# Characteristics (PC1–PC12)

Qualities of a good Policy Report. Violations are ADVISORY findings — they
inform the user and ride into the final document's advisory appendix; they
never block a group.

| ID | Characteristic | A good report… |
| --- | --- | --- |
| PC1 | Clear | …uses plain language a non-specialist affected employee can follow; jargon only when defined in PA15. |
| PC2 | Testable | …has policy statements a verifier can judge pass/fail from the statement alone. |
| PC3 | Single-subject | …keeps one concern per statement; compound obligations are split. |
| PC4 | Modal precision | …uses MUST/SHOULD/MAY exactly per definitions.md, one modal per statement. |
| PC5 | Consistent terminology | …uses each key term exactly as PA15 defines it, everywhere. |
| PC6 | Complete | …substantively populates every required attribute, and every conditional one whose condition holds. |
| PC7 | Current | …cites regulations, standards, and related policies that are in force, not superseded. |
| PC8 | Accountable | …assigns every duty its statements create to a named role in PA23. |
| PC9 | Proportionate | …imposes requirements proportionate to the risk in PA14 — no controls without a driver. |
| PC10 | No placeholders | …contains no empty, TBD, or placeholder values in required attributes. |
| PC11 | Enforceable | …pairs its statements with monitoring (PA25) and consequences (PA26) that make them real. |
| PC12 | Self-contained | …reads without external context: acronyms expanded once, references resolvable from PA16/PA17. |
